# 续写

续写要接得上。正文、剧情记录和人物状态对着同一个章节结束点，新写的一章从上一章的末尾长出来。

记录的格式和每章写完以后的同步办法在 `references/records.md`。

## 写前恢复上下文

1. 跑 `python scripts/novel_status.py <小说根目录>`。看最新章节是哪一章，章纲细化到哪一章，各份记录同步到哪一章，有没有缺号和重号。记录落后于正文，先按 `records.md` 补齐记录再续写。
2. 按脚本给出的“续写前先读”清单从文件里读。项目说明，现行总纲，当前卷的章纲，四份进度记录和文风卡。核对版本，`存档/` 里的旧稿不算数。
3. 读上一章的全文。再按这一章要用到的人物、伏笔和旧事，回去查对应的章节原文。记录不能代替必要的原文核对。几百章的书不必通读，用搜索按人名、物名找到那几处。
4. 在心里确认这些。现在是第几卷第几章，故事时间，人在哪里，跟着谁的视角，各人的状态，近期要兑现的事，哪些转折不许提前发生。
5. 读 `references/living-prose.md` 和 `references/drafting.md`，然后写。

同一次对话里刚写完上一章接着写下一章，前面的文件内容还在眼前，可以不重读，但上一章的末尾要再看一遍。隔了一次对话，就一定从文件读。

## 事实、设定和计划分开

- 已经发生的事以现行正文为证。总纲和章纲只约束未来。人物设定里的东西没在正文出现过，算设定已确认、正文未登场。
- 不能把卷末的境界、未来的死亡、结局的关系和未来的年龄写成人物现在的状态。
- 角色说的话、猜测和传闻，保留是谁说的、有多可信。秘密不提前泄露，角色不凭空知情。
- 用户这一次明确的修订优先。发现正文和大纲有重要冲突，记下来并核对来源，不悄悄改写已成的事实，不擅自改核心结局。只有会挡住这次写作的冲突才需要问。
- 用户只要章纲、试写、候选片段或风格示范，存到 `草稿/`，不推进正式进度。用户要正式续章，写完就是现行正文，不必逐章请用户批准。

## 接住文风

写之前看 `创作记录/文风卡.md`，照着它的人称、称谓、对白格式和句子习惯写。没有这份文件就按 `records.md` 从已有正文里取样建一份。

原稿的文风和本 Skill 的默认写法不一样时，跟原稿走。只有成稿硬禁令在新写的部分照样执行，不回头改用户已有的正文。

## 只有正文没有大纲

用户丢过来一段或几十章正文，说接着写，没有任何大纲和记录。

1. 把正文按章存进 `正文/`。整本书在一个文件里的不必拆，`novel_status.py` 会按文件里的章节标题统计。
2. 从正文里反推并落盘。文风卡。主要角色记录，只写正文里有依据的。已发生总结。还没回收的线索和悬念，记进未发生待办并注明“从正文反推”。世界规则里已经露出来的部分。
3. 写一份暂定的后续规划，三到五章，放进 `紧接章节计划.md` 并标暂定。它要接住正文里已经立起来的目标和悬念，不另起炉灶。
4. 然后续写。交付时告诉用户后续规划是暂定的，请他看一眼方向。

反推出来的东西不能假装是原作者早就定好的。拿不准的写“未设定”或者给一个范围。

用户明确说了后面怎么走，就以他说的为准，不必另出规划。

## 章纲用完了

状态脚本提示最新章节已经到了章纲的最后一章，或者超过了它。

这一卷还没写完，就读 `references/outline.md`，按总纲里这一卷的分卷纲把后面的章纲补出来，一次补五到十章，再续写。

这一卷写完了，按下面的跨卷办法开新卷，给新卷建章纲文件。

## 改稿以后

删掉或改写了一件事，撤销相关的核销，更新受影响的总结、人物状态和后续计划。

后面已经有写好的章节，就扫一遍哪些地方依赖被改的内容，把矛盾列出来。没有得到许可，不为了账面一致去扩大重写的范围。

## 跨卷

卷末保留这一卷的总结和完成记录。还有效的遗留事项带到下一卷，沿用原来的编号，原卷注明转到哪一卷，新卷注明来自哪一卷，后续状态以新卷的记录为准。人物记录接着更新，不重置成新卷大纲里的终点。

开新卷之前做这些。

- 重读总纲里的主线、年表和硬性约束，上一卷和新卷的分卷纲。
- 从上一卷最后一章的全文往前回读，一直读到能说清眼下的局面是怎么形成的。早先埋下、要在新卷接上的线索，回去查它最初出现的那场戏。
- 在新卷的紧接章节计划里写一段跨卷承接。上卷结束时的时间、地点、人物状态和没做完的事，新卷从何时何处接进来，中间过了什么，依据来自哪几章。
- 重点核对行动的因果、情绪的余波、关系的变化、伤病和资源、年龄和能力、知情范围、没兑现的承诺和伏笔。

写完新卷开篇以后，把上卷结尾和它连着读一遍。时间说得通，动机成立，过渡不突兀，才算接上了。

## 交付前核对

章节顺序，时间和年龄，位置和行程，能力，伤病，物品的去向，关系，知情范围，逐项看接不接得上。

标了已完成的事项都有正文证据。没写出来的事还留在待办里。紧接章节计划确实是从当前的章末开始的。

再跑一次 `novel_status.py`，确认四份进度记录都同步到了最新一章。
