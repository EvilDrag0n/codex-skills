# 初稿写完以后

这一份只在初稿写完以后读。改稿先保住已经活着的地方，再拆模型摆出来的姿势。不要把一章修到没有毛病，也没有人。

## 第一遍接不接得上

对着上一章的结尾和 `创作记录/` 看。

- 开头接住了上一章没做完的动作和没散的情绪没有。
- 时间、地点、谁在场，和上一章对得上没有。
- 伤还在不在，东西在谁手里，钱花没花。
- 每个人说的话和做的事，有没有用到他此刻不该知道的信息。
- 能力有没有越出世界设定的边界，越了的话代价写了没有。
- 这一章有没有写到章纲里留给后面的事。
- 称谓和文风卡一致没有。新书第一章还没有文风卡，这一条跳过。

## 第二遍每场戏有没有往前走

给每场戏标一下，进场时谁要什么，出场时什么变了。标不出来的那一场，压成几句概述或者删掉。

再给每一段标一个主要作用，动作、对白、心理、环境、背景、过渡。连着几段只做同一件事，通常就拖了。

做一次压缩试验。删掉三分之一以后，事情、选择和读的感觉几乎没变，原稿就是在注水，留下删短的版本。

看有没有压缩过头。找到这一章最要紧的那个选择，看它是不是在场景里发生的。被一句概述带过去，或者用“他站了很久，后来动手了”跳过去，都要补。读者得看见是什么让他倒向这一边。

背景和设定逐处问，删掉以后人物的选择和这场戏的风险变不变。不变，就是来早了，或者根本不用来。

## 第三遍人物

- 主角这一章做了选择没有，还是一直被推着走。
- 关键选择的前后，读者知不知道他在权衡什么。
- 人物的推断有没有跳步。他从看见一样东西到下结论，中间每一步读者跟不跟得上，还是叙述者替他把结论说了。
- 有没有叙述者替读者记账的句子，比如点明这是他今晚第二次撒谎。读者自己数得出来的，删掉。
- 配角有没有自己的事，还是只在递消息、捧场。
- 有没有谁忽然变聪明或者变蠢，只为了让情节走得通。
- 对手这一章做的事，站在他那边说不说得通。
- 主角得到的东西付了代价没有。

## 第四遍对白和动作

把对白单独抽出来读。

- 遮住说话人，能不能听出是谁。
- 有没有两个人都知道、只为读者念一遍的话。
- 有没有人在替作者讲道理。
- 每一句是在试探、遮掩、说服、拖延、靠近还是推开。什么都不是的删掉。
- “冷冷地说”“淡淡地道”“缓缓开口”这类带副词的提示语排着出现的，多数换成“说”，或者换成一个动作，或者直接去掉。

圈出点头、摇头、耸肩、叹气、皱眉、笑了笑、看了一眼、顿了顿。每一处问它带没带态度。不带的删掉，或者换成这个人此刻才会有的动作。

圈出动作后面跟着的情绪解释。读者已经看得出他在犹豫、害怕、舍不得，就删掉那句解释。动作看不出来的心理留着。

## 第五遍句子和套语

读出声，或者在心里一个字一个字过。

- 哪里要回头找主语，把人和动作提到前面。
- 哪里一口气读不完，拆开。哪里连着短句像敲桌子，合并。
- 连词删一半，读不断就不补回来。
- 同一个人、同一样东西的叫法前后一致没有。
- 有没有用词出戏。
- 对照 `references/living-prose.md` 的模型套语表。同一类出现三次以上的，回到人物此刻的处境里重写。
- 外貌有没有从头排到脚。只留一处。
- 比喻落下以后有没有跟着解释。删掉解释。

## 第六遍清禁用项

对照 `references/living-prose.md` 的成稿硬禁令逐条搜，八项都要清零。

其中三项脚本认不全，这一遍要自己查。

- 三项以上的同构排比。找连着三个以上用同一个开头或同一个句型的小句和句子。
- 给抽象名词配具体动词的抒情。找时间、岁月、命运、沉默、孤独、记忆这类词后面跟着保管、磨平、吞没、发芽这类动作的句子。
- 章末和卷末的升华。看最后两段有没有叙述者的评语、预告和感慨。

翻案腔按动作查，不只按字面查。逐段问一句，这里是不是先立了一个读者并没有的误解，再推翻它。是，就找到这句话原本想下的判断，从正面说出来。

修改违禁句时，先找它原本想说的事，再用普通句子说出来。不要找另一种漂亮句式来替换。

## 第七遍章末

把最后一段删掉再读，更有力就让这一章提前结束。再删一段试试。

最后一句如果是叙述者的评语、预告或者感慨，换成一件事，或者删掉。

搜一下命运、未来、时代、从此、一切、所有人。这一章没有一直在处理那么大的尺度，就回到眼前的人和事上。

开头出现的东西在结尾又回来时，确认它的含义已经变了。没变就不必回来。

## 跑检查脚本

```text
python scripts/check_chapter.py 正文/第1卷/第001章\ 标题.md --target 3000
```

系统里只有 `python3` 就用 `python3`。可以一次传多个文件。给了 `--target`，脚本会打印字数偏离目标多少，偏离超过百分之十五就提醒，这个比例可以用 `--tolerance` 改。

脚本把结果分成两类。

“需要修改”的项必须清零。包括破折号、提示性冒号、叙述里的翻案句、硬停词、模型路标和商业黑话。这是八项硬禁令里脚本能自动判定的部分。

“需要人工判断”的项逐条看。包括对白里的翻案句式、排比、疑似抽象抒情、章末升华、模型套语扎堆、外貌堆砌、不带态度的小动作、情绪标签、模糊词、廉价转折、带副词的对话提示语、句长过齐、超长段落、疑似设定说明段、段首重复、字数偏离。人物真会这么说、这场戏确实需要，就保留。密度类的提醒有门槛，零星出现的一两处不报，要靠第四遍和第五遍自己看。

脚本不查这些位置的冒号，引用块（行首 `> `）、【】里的文字、标题行。系统面板、书信、告示放在这些位置里。

脚本只认形状，认不出这一章有没有人。一份认真改过的稿子，脚本多半全绿，这不说明写得好。人物的推断跳没跳步、关键选择有没有被带过，它一条也看不见。

环境里装了 human-writing 时，还可以再跑它的 `scripts/check_prose.py`。它不区分叙述和对白，对白里的句式也会报，按人物的说话习惯判断留不留。在 Windows 的控制台里它的输出可能是乱码，命令前面加 `PYTHONUTF8=1` 就好了。

放下所有规则，回答 `references/living-prose.md` 末尾的五个问题。
